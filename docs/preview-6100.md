# 6100 预览版：GSCore 兼容与插件目录修复

版本：`0.2.0-preview.1`；开发分支：`preview/6100-gscore-store`。

本版供独立容器预览，不替换6099生产实例，不自动导入QQ账号数据、旧插件配置或GSCore Token。

## 内置 GSCore 与旧插件的区别

内置版重视管理鉴权、Token脱敏、有限退避、心跳、连接代次、资源限制和只允许固定的消息发送动作；旧插件还包含群开关/黑名单/管理命令、事件上报、撤回回执、禁言等更多特性。两者不是完全等价替代。

### 本次已修复/补齐

| 问题 | 旧内置版现象 | 预览版处理 |
| --- | --- | --- |
| 引用消息 | 将消息ID放进reply字段 | reply_id保存ID，使用get_msg补引用正文和已支持媒体；上下文失败时保留ID并报告 |
| 私聊文件 | 字段名不匹配、经常没有下载URL | 兼容file/name，使用get_private_file_url只读查询补URL；无可用URL时明确跳过文件段 |
| link://图片/文件 | 不识别旧插件常用格式 | 仅剥离安全HTTP(S)包装，不允许file://或本机路径 |
| 裸base64 | 旧内置不接受 | 校验后规范化为base64://，仍有尺寸限制 |
| reply_id与markdown出站 | 作为未知段拒绝整条 | reply_id转换OneBot引用；Markdown降为普通文本 |
| 混合文本/节点/文件 | 仅支持单独一个node/file | 全计划先验证，再按顺序执行有限动作；节点深度/总段数/总大小有限制 |
| 引用/转发上下文 | 缺少补充解析 | 固定白名单只读动作展开，超时/次数/递归循环受限 |
| 自然断线后的旧任务 | 已排队任务可能穿过新的连接 | socket lease贯穿异步解析、队列和每个发送动作；旧连接任务失效 |

“全计划先验证”验证的是协议格式与资源限制；实际QQ动作仍可能因权限、网络或原生层返回失败，多动作发送不提供事务回滚。已经提交给QQ的单个原生请求无法保证被取消。

### 仍未覆盖/保留的限制

- 不开放任意OneBot动作，撤回、禁言、执行管理动作没有为了旧插件兼容而放开。
- 旧插件的完整notice/meta事件、echo撤回回执、群配置、黑名单和本地管理命令仍需单独适配。
- 复杂转发、特殊媒体、频道等并不保证100%兼容；超出深度/段数/大小限制会拒绝或退化提示。
- 上下文查询超时不等于取消QQ原生查询，只是停止本次等待；不读取生产账号数据来做测试。
- 不能同时开启旧插件与内置桥接，避免重复收发。
- 此版协议测试包含stub动作和本地WebSocket，未替用户发送真实群聊/私聊业务消息。

## 插件商店为什么报错

原代码只依赖 `NapNeko/napcat-plugin-index/main/plugins.v4.json`，核查时该地址返回HTTP404。旧逻辑会串行尝试多个镜像且每个等待10秒，最终整页错误。

### 新行为

- 首次立即展示随版本提供的保守目录；原始官方来源在后台检查，全流程最多4秒。
- 同一请求单飞，强制刷新有60秒冷却；成功目录缓存仅用于浏览。
- 明确显示在线/缓存/随包目录、最近检查和失败原因摘要，不假装恢复了所有原商店插件。
- 随包列出内置GSCore、缓存清理、插件诊断，以及SSQQ官方项目页；内置实现与第三方插件不冒充同一个包。
- 不再自动加载第三方头像、站外README或favicon服务，外部页面由用户主动打开。
- 远端JSON和URL视为不可信数据，限制体积、字段、条目、重定向及链接格式。

### 在线安装暂不恢复

旧安装路径未验证包完整性，且会先删除现有插件再解压。预览版移除此路径，POST和SSE安装接口均拒绝执行；不能通过mirror、downloadUrl或force参数绕过，也不把远端声明的SHA当作独立认证。

恢复的是“可浏览目录、内置工具入口、原作者页面”，不是“所有旧插件的一键安装”。后续需有可追溯包、独立校验、受限解压与原子替换/回滚才能重新开放。

## 预览实例约定

- 宿主端口6100映射容器6099；生产6099不改。
- 使用独立QQ/config/plugins目录，默认QQ未登录、内置GSCore关闭。
- WebUI管理Token沿用当前管理Token，方便用户预览；它不等同于QQ登录态。
- 不要在预览实例扫码登录生产正在使用的同一QQ，否则可能互相挤下线；可先看UI或使用独立测试账号。
- 生产现有GSCore/SSQQ插件继续运行，不因为本次改造被关闭或替换。
